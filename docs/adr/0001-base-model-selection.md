# 0001 — 基座选型：laya-multilingual(322M) + RLCD 微调

- 状态：已接受（2026-10-12）
- 影响：#3 / #7 / #12 / #6 的训练与评测口径

## 背景

mai-jev 要一个**中文优先、可自持权重、能跑在低端设备上**的 System One 决策模型。三条候选路线：

| 路线 | 是什么 | 结论 |
| --- | --- | --- |
| a) 从头训中文编码器 + 决策头 | 自己初始化 ModernBERT 类编码器，从零学 choice/score/noul 三原语 | ❌ |
| b) Kev / Qwen3.5 0.8B–9B 解码器 | 用自回归解码器做决策 | ❌ |
| c) SemIf 式零训练复刻 | 读现成 LLM 的 token 概率，不训练 | ❌ |
| **d) laya-multilingual + RLCD 微调** | 在开源 322M 编码器决策模型上做强化微调 + 温度标定 | ✅ |

## 决策

选 **(d)**：基座 `convaiinnovations/laya-multilingual`（mmBERT-base 322M 编码器 + 2 层决策头，Apache-2.0），用 RLCD 微调，再在留出集上拟合温度把 ECE 压到 ≤0.10，最后量化导出。

### 为什么不是 (a) 从头训

- 预算不允许：单轮实验 ≤4 小时、最多 3 轮，从零训一个编码器在 3 万问题量级上学不到可用的中文决策能力。
- 决策头本身是轻的（2 层 Transformer + 选项打分器），难点全在编码器的中文语义表征；重复造轮子没有收益。
- 零样本摸底已证明预训练表征有用：`laya-multilingual` 在中文工单上 choice 置信度 0.9956、noul 0.9941，只是 score 与校准不可用 —— 缺的是领域适配与标定，不是表征。

### 为什么不是 (b) Kev / Qwen3.5 解码器路线

- 自回归解码是 System Two 的计算图：逐 token 生成，延迟与算力随输出长度线性增长，低端设备上 p50<50ms 不合格。
- 0.8B 起跳，量化后仍远超 ≤1GB 常驻内存预算。
- 拿不到逐选项的校准概率分布，ECE ≤0.10 的验收线无法直接达成。

### 为什么不是 (c) SemIf 零训练复刻

- 不训练就没有可发布、可自持的权重，"训练后发布到 ModelScope 与 HF"这一目标直接落空。
- 读现成 LLM 的 token 概率等于把模型绑死在某个外部 LLM 上，与"低端设备离线可用"冲突。

### 为什么不是用 Jev API 打标

- 合规：Jev 是 TypeSafe AI 的闭源云 API，服务条款不允许用其输出训练衍生模型。
- 可用性：据报道未对中国大陆开放。
- 校准污染：会把新模型校准到老师的错误上 —— Jev 出厂 ECE 约 0.466，我们恰恰要修的就是这件事。

## 后果

- 训练管线必须复用 Laya 的 RLCD 奖励（严格适当评分规则 + GRPO 组基线），不能换成交叉熵 —— 见 CONTEXT.md 对 RLCD 的定义。
- 必须预留 calib 留出集做温度标定；出厂权重自带温度超界（会被 laya 钳到 0.5），原版置信度不可信。
- 衍生模型需保留 Apache-2.0 声明、Laya 原作者署名与修改说明（#11）。
